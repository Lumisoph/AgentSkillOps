# AgentSkillOps 实验报告

## 研究问题

实验围绕一个部署风险展开：动态技能库若依据噪声较大的单次评测自动删技能，可能把短期波动
误判成长期伤害。研究依次检查测量是否可靠、价值位于哪个层级，以及基于探索集选出的规则能否
在留出任务上成立。

## 实验设置

- 环境：ALFWorld；模型侧以 1.5B Agent 的 SFT、RL checkpoint 10/20/30/40 为主。
- 单技能测量：同一任务顺序和随机种子下，比较 full bank 与 leave-one-out。
- 主评测预算：每个条件 140 个任务；独立验证另使用 134 个 OOD 任务和 200 个
  `valid_train` 任务。
- 统计方法：配对效用与标准误、McNemar 检验、bootstrap 区间、Bonferroni/BH 校正、
  预先固定的 5 个百分点非劣界。

仓库保留支撑下列数字的配对 CSV 和汇总 JSON；模型权重与逐步轨迹不公开。

## 证据链

### 1. 单技能判决的信噪比不足

6 个 general skill、最多 5 个 checkpoint，共 26 个 `(skill, checkpoint)` 单元。多重比较
校正后没有单元显著，`mean(|z|)=0.73`，与零效应下的理论水平接近。这一结果只说明当前预算
不能稳定识别典型单技能效应，不等价于“技能都无效”。

真实配对数据的 200 次分半检验中，平滑后验的校准误差从 `0.210` 降至 `0.073`。该结果说明
跨 checkpoint 聚合比单点 plug-in 更适合当前数据，但不证明模型已被普遍校准。

### 2. 技能库有价值，但原先测量的单位可能不对

完整 bank 相对 no-skill：

| checkpoint | no-skill SR | full SR | 配对差值 |
|---|---:|---:|---:|
| 20 | 0.164 | 0.279 | +0.114 |
| 40 | 0.136 | 0.271 | +0.136 |

在 checkpoint 40 的 2×2 分解中：

| 条件 | SR |
|---|---:|
| none | 0.136 |
| general only | 0.179 |
| task-specific only | 0.271 |
| full | 0.271 |

task-specific 主效应为 `+0.114`，bootstrap 95% CI 为 `[+0.057,+0.171]`；general 主效应
为 `+0.021`，区间 `[-0.021,+0.064]`。因此可以说该 checkpoint 的可检出价值主要位于
task-specific 层，不能推广为所有模型和 checkpoint 的恒定规律。

### 3. 探索集上的精细规则没有通过独立验证

探索分析提示 clean/cool 组有正向信号，于是固定“general + clean/cool”的 selective 规则，
在 134 个 OOD 任务上与 full bank 比较。结果为 `-0.052`，精确区间
`[-0.078,+0.003]`，未通过 `-0.05` 非劣界。损失来自被排除组中的真实成功任务。

这个负结果区分了两件经常混在一起的事：某个小组「未检出收益」不代表已经「证明无收益」。探索数据适合
定位问题，不适合同时选择规则并宣称规则有效。

### 4. TS Only 是较强基线，但边界仍需保留

在同一批 OOD 任务上，task-specific only 相对 full 为 `+0.037`，精确区间
`[-0.030,+0.091]`，且平均 prompt token 降低 `12.5%`，通过预设非劣界。

在另一 checkpoint 与 200 个 `valid_train` 任务上，两者成功率均为 `0.29`，prompt token
降低 `8.7%`，但精确区间下界为 `-0.056`，距离非劣界差 0.6 个百分点。因此最稳妥的表述是：
目前没有观察到整体移除 general 的性能伤害，且成本稳定下降；单数据集证据仍不足以确认它在
所有策略与任务分布上非劣。

### 5. “暂态伤害会恢复”未获支持

增加到 5 个 checkpoint 后，AR(1) 的 `phi` profile 95% CI 仍为 `[0,1]`，过程方差趋近
边界。数据没有足够的时间变异来区分暂态恢复与持久伤害，所以停止围绕该假设继续扩展算法。
状态空间实现仍有价值：它把不可识别性变成可检查的输出，并阻止系统依据不稳定点估计做永久
动作。

## 可以声称与不能声称

可以声称：

- 构建了从配对效用测量、跨 checkpoint 建模到技能状态决策的可审计链路；
- 在当前实验中识别出单技能 LOO 信噪比不足和管理层级错位；
- 用独立任务验证推翻了一个在探索集上看似合理的 selective 规则；
- TS Only 在两批任务上都降低 token，且点估计未显示性能损失。

不能声称：

- 找到了全局最优的技能退休参数或普遍最优的技能子集；
- `phi` 已被可靠估计，或技能伤害一定会随训练恢复；
- 未显著的技能/任务组已经被证明无用；
- 1.5B、ALFWorld 上的结论会自动迁移到其他模型、环境或检索器。

## 工程意义

这次实验改变了我对技能库维护的判断。问题不在于还缺一个更复杂的退休公式，而在于系统尚未
确认自己测对了对象。自动修改长期记忆前，我会先检查测量误差、归因单位和动作代价，再看规则
能否通过分布外验证。本项目里，负结果的直接用途就是阻止证据不足的永久删除。
